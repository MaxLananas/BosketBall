# Infrastructure research (2026-11-08)

## Paper and workload design

* [Paper scheduler guidance](https://docs.papermc.io/paper/dev/scheduler/) says synchronous work shares the game thread; file, network, and database work belongs off-thread, but world state access or mutation is not safe from async tasks. Ticks are not a wall clock under lag. Decode schematic bytes asynchronously; schedule world writes on the owning server thread, and do not invoke Bukkit world APIs in the decoder.
* [Paper world configuration](https://docs.papermc.io/paper/reference/world-configuration/) documents per-tick chunk autosave limits, asynchronous chunk unload saving, and the costs of unloading. [Paper's chunk discussion](https://forums.papermc.io/threads/help-to-find-lag-causes.625/) notes that `getChunk()` can trigger a synchronous wait even when chunk work is otherwise asynchronous. Chunk loading, generation and lighting must be measured separately from block placement; a block-count limit alone is not a time guarantee.
* [Paper's entity activation documentation](https://docs.papermc.io/paper/reference/spigot-configuration/) explains that entity ticks are distance dependent, and [world configuration](https://docs.papermc.io/paper/reference/world-configuration/) distinguishes chunk ticks from block-entity ticks. Reducing activation ranges is a gameplay change, not a substitute for profiling bots, displays, and player updates under load.
* [FAWE's documented queue design](https://intellectualsites.github.io/fastasyncworldedit-javadocs/worldedit-core/com/fastasyncworldedit/core/Fawe.html) queues chunk changes, coalesces lighting and packets, and handles side effects explicitly. Its [queue API](https://intellectualsites.github.io/fastasyncworldedit-javadocs/worldedit-core/com/fastasyncworldedit/core/queue/implementation/SingleThreadQueueExtent.html) exposes a target queue size and chunk preload. This is not permission to call Bukkit world methods asynchronously: a staged Bukkit implementation must budget *all* writes, including attachable repairs, door closure and block-entity restoration, and protect cancellation and partial courts.
* [Paper recommends spark](https://docs.papermc.io/paper/reference/commands/) for performance profiles. Run a realistic 16-player workload and report distributions, not a single average; include queue wait and maximum tick time, and treat a missed 50 ms tick as a failure. Plugin timings cannot establish the absence of pauses in other plugins, chunk generation, garbage collection, or the operating system. Pre-warn when a chunk load or expensive phase is about to start; retrospective warnings cannot prevent a spike.

## Build and reproducibility

`tools/build_plugin.py` sorts archive entries and fixes ZIP timestamps and permissions before hashing the resulting bytes; it must check assets before packaging and must fail when a referenced custom item, model, texture, or glyph is missing. A static checker must account for dynamically composed model names and distinguish vanilla assets from pack-owned ones. Test negative fixtures and build twice, comparing archive SHA-1 bytes. Hash stability is not proof that the CDN has the same pack.

## Findings in this checkout

* Paste completion originally invoked `closeDoors`, `repairAttachables`, and `applyBlockEntities` in one tick. These passes are now sliced too, with the decoration watchdog deferred while a paste is queued. The 4,000-index cap does not bound entity cleanup, chunk loading, lighting, display creation, or unrelated plugin work in that tick; it is not a wall-clock guarantee.
* `Achievement` uses `icon_fire` as an item model; it now has an item/model definition reusing the existing font texture. Five stale locker HUD font providers were removed from uniform and its custom glyphs synchronized with default, consistent with the generator. The expanded guard catches known literal ID families, ball mannequin derivations and bitmap-font textures, but cannot prove arbitrary dynamic Java data flow.
* `origin/main` contains an asset-only upload with over 200 root-level PNGs; it has no JSON model definitions in its tree. It differs radically from the arena base and cannot safely be merged wholesale. Only the missing item definition and stale font references were reconciled here; no images were imported or redrawn.
* Startup validation covers bundled value types and selected numeric ranges, strings, lists, enums, dates and cross-field checks, not every semantic constraint or per-key comment. The existing compatibility test requires pre-v7 shot-clock and gravity values to clamp; migration now persists normalized numeric values so a subsequent restart can read them. Some legacy migration behaviour, including the existing large paste-budget cap, is still permissive rather than failing.
* A workload-level tick guarantee is not established by a unit test or by the build. A Paper 26.2 server with real clients and a profiler is necessary to validate it.

* Debug sampling now aggregates inclusive match and schematic steps and targeted HUD/bot costs per scheduler tick. The categories overlap; none is full-server MSPT. See the integration note for scope, startup flag and the required real-workload validation.
