# Infrastructure integration gaps

This is not a finished tick-budget report. `TickProfiler` currently records averages and maximums for `match`, `schematic`, `sidebar`, and other top-level UI steps; it does not separate match HUD or bot costs, and does not retain p50/p99 samples. The match director owns `MatchSession.java`. A complete implementation needs a bounded sampler and debug switch, then nested timing around the bot squad and sparring bot, shot-charge and live HUD, scorebug and ceremony HUD, and the full session tick, with `finally` blocks so exceptions do not corrupt samples. Samples for different sessions in one tick need aggregation before calculating per-tick percentiles. HUD and bots are included in the inclusive match number and must not be added to it as independent totals.

The asset owner needs to add a valid `bosketball:icon_fire` item definition (used by `Achievement.iconModel()`) and reconcile the five `locker_hud_*` bitmap references in `minecraft/font/uniform.json`. Until then a full dynamic Java/icon/font guard cannot be enabled without turning the build red. `tools/check_pack_models.py` verifies direct literal `customIcon` calls plus references inside shipped item/model JSON, but is not a complete Java data-flow or font audit.

Paste cancellation/resumption is exposed as `SchematicCourtPool.cancelPaste(arenaId)` and `resumePaste(arenaId)`, to be called from the server thread. The existing repaste-all command resumes cancelled courts. A cancelled court remains unavailable and its partial blocks remain in the world. Cancellation, unload/reload, restart and world-side effects still require integration tests on a running Paper server. The 4,000-index cap is not an MSPT guarantee: final display creation, chunk loads, entity cleanup and lighting are not bounded by it.
